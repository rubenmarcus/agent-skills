# A bounded implementation spec

```text
Source and revision:
Problem / concrete trigger:
Expected behavior:
Existing behavior and evidence:

In scope:
Out of scope:
Compatibility, data, and authorization contracts:
Unknown decisions that matter:

Acceptance criteria:
- Observable result:
  Verification method and scenario:

Implementation slices and dependencies:
Ownership / isolation:
Required project checks:
Runtime or human evidence still needed:
Next concrete action:
```

Use only the sections the task needs. Each implementation slice should produce useful evidence or a reviewable change. Avoid splitting a tightly coupled contract between concurrent writers.
