# Working on this collection

Read `CONTINUATION.md` before resuming. Keep the full package and article objective visible there.

Skills live in `skills/<name>/SKILL.md`. Each must work from its own folder with relative references and must describe a distinct task. Preserve the user's chosen tools and scope. Explain platform-specific capabilities as adapters; do not require a particular agent or a running service for a generic method.

Write new instructions, not copies of private project documents. Record source revisions in `PROVENANCE.md`. Do not vendor third-party suites, source projects, credentials, customer data, or generated bulk artifacts. Keep skill content separate from article and release notes.

Run `npm run check` after package changes. Run the documented focused fixture checks after changing executable examples. A structural check does not prove model behavior. Keep real-agent evaluations and publication status explicit.

Do not activate these skills globally as a side effect of editing the collection. Preserve existing hooks when helping a user install hook examples.
